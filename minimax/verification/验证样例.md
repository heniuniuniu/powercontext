# 验证样例 T1：订单列表新增 status 筛选

## 1. 任务描述（要改什么）

为 `demo_app/filter.py` 的 `list_orders` 增加可选参数 `status`：传入时只返回该状态的订单，
且**必须先过滤再分页**。

## 2. 哪些原有行为必须保持

- 不传 `status` 时返回值与修改前完全一致。
- 分页仍从 `page=1` 起、`page_size` 生效；越界返回空列表不抛异常。
- 排序仍为 `created_at` 降序、相同则 `id` 升序。

对应回归用例：`test_pagination_unchanged`、`test_sort_order_unchanged`、
`test_out_of_range_returns_empty`。测试集在修改前后完全一致。

## 3. 有效规格与初始数据

- 当前生效规格：`corpus/specs/order-filter.md`（SPEC-ORDER-014 v2）。
- 初始数据：`tests/test_order_filter.py` 顶部 `ORDERS`，6 条订单，覆盖
  `paid` / `pending` / `cancelled` 三种状态与不同时间戳。
- 修改前代码：`demo_app/filter.py`；修改后代码：`demo_app/filter_after.py`。

## 4. 上下文必须包含的来源

| 段 | 必须出现 | 核对方式 |
| --- | --- | --- |
| specs | `corpus/specs/order-filter.md`，且含「先过滤再分页」 | `context` 输出 `specs[].text` |
| code | `corpus/code/filter.py` 的 `def list_orders` | `context` 输出 `code[].text` |
| tests | `corpus/tests/test_order_filter.py` 的 `test_status_filter` 与三个回归用例 | `context` 输出 `tests[].text` |
| state | 上一轮已完成/待办/验证结果 | `context` 输出 `state` |

更新规格复核：把 `corpus/specs/order-filter.md` 中「先过滤再分页」改成另一条明确规则后
执行 `python -m sdd_context.cli import --dir corpus`，再执行 `context --task T1`，
输出的 `specs[].revision` 递增且正文为更新后的内容 —— 证明不是固定答案。

## 5. 操作步骤

```bash
docker compose up -d
export SEEKDB_DSN='root@127.0.0.1:2881/sdd'

python -m sdd_context.cli init --reset
python -m sdd_context.cli import --dir corpus
python -m sdd_context.cli context --task T1 | tee logs/context-before.json
python -m sdd_context.cli save --task T1 --done "上下文已组装" --todo "应用补丁并跑测试"
# 模拟跨会话：退出进程后重新执行，state 段应读到上一轮记录
python -m sdd_context.cli context --task T1 | tee logs/context-resumed.json
python -m sdd_context.cli verify --task T1
python -m sdd_context.cli context --task T1 | tee logs/context-after.json
```

## 6. 预期结果

- `context-before.json`：四段均非空、来源路径真实存在、state 为「首次运行」。
- `context-resumed.json`：`state.done` 含「上下文已组装」，`state.todo` 含「应用补丁并跑测试」。
- `verify`：修改前退出码 1（`test_status_filter` / `test_status_filter_before_pagination`
  因 `TypeError: list_orders() got an unexpected keyword argument 'status'` 失败，属于功能缺失，
  不是依赖缺失或启动失败）；修改后退出码 0，5 个用例全绿。
- `context-after.json`：`state.verification.passed == true`。

## 7. 重置方法

```bash
python -m sdd_context.cli init --reset
rm -rf state/ logs/*.log
cp demo_app/filter.py.before demo_app/filter.py   # 或从 corpus/code/filter.py 拷回
```

`corpus/code/filter.py` 始终是修改前快照，可直接拷回 `demo_app/filter.py` 复位。
