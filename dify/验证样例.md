# 验证样例：同一玩家连续两轮，检查记忆是否被复用

## 初始状态

- 桥接层已启动，`GET /health` 返回 `{"ok": true, ...}`。
- 干净起点：删除 `memory-store.json`（本地兜底模式）或在 PowerContext 中清空 `player:小舟` 的记录。
- Dify 已导入 `brainstorm-debate.yml`，`主持人串词` 节点已绑定可用模型，环境变量 `PC_BRIDGE_URL` 指向桥接层。
- 如使用真实 PowerContext，记录 `/health` 里的 `powercontext_configured: true`，以及本次验证所用版本。

## 第一轮：冷启动

| 项 | 内容 |
| --- | --- |
| 玩家昵称 | `小舟` |
| 今日辩题 | `午休该不该关灯` |
| 我站哪边 | `关灯派` |

操作：在 Dify 运行界面填入三项 → 点击运行 → 等待流程结束。

预期：

1. `读取往期记忆` 节点返回「（这位玩家还没有往期记录）」或空数组。
2. 输出包含【本轮串词】（开场、正方、反方、收束 4～6 句）和【本轮新梗】一行，两段结构齐全。
3. 串词里不出现「上次你说过……」。
4. `写回记忆` 节点返回 `ok: true`；桥接日志出现一条 `POST /memory/write`，`memory-store.json` 新增一条 `player=小舟` 记录。

## 第二轮：记忆复用（关键验证）

| 项 | 内容 |
| --- | --- |
| 玩家昵称 | `小舟`（必须与第一轮一致） |
| 今日辩题 | `会议室的椅子有没有领地意识` |
| 我站哪边 | `有` |

操作：新开一次运行（模拟新会话），重新填入三项 → 运行。

预期：

1. `读取往期记忆` 节点返回第一轮写入的串词与新梗，可在节点执行记录里看到非空 `body`。
2. 【本轮串词】里出现对第一轮内容的呼应，例如「上次你说过……」，且呼应内容与第一轮输出一致，不是新编的。
3. 【本轮新梗】与第一轮不同。
4. 桥接日志再出现一条 `POST /memory/write`，`memory-store.json` 里有两条 `player=小舟` 记录。

这一条对应验收标准里的「记忆如何被保存并在后续互动中复用」，不是只测一次连接。

## 第三轮：换玩家隔离

| 项 | 内容 |
| --- | --- |
| 玩家昵称 | `阿岚` |
| 今日辩题 | `群里回收到算不算已读` |
| 我站哪边 | `算` |

预期：`读取往期记忆` 返回空，串词里不出现 `小舟` 的旧梗；写回记录里 `player=阿岚`。用于确认记忆按玩家隔离，没有把所有人的梗混在一起。

## 需要留存的证据

- 三轮 Dify 运行的输入截图、输出文本，以及 `读取往期记忆` / `写回记忆` 两个节点的执行记录（含请求 URL 与响应体）。
- 桥接层终端日志或 `memory-store.json` 内容片段，展示 `player`、写入时间与内容。
- 若使用真实 PowerContext，附该侧的记忆列表或查询记录截图，标明 `source: powercontext`。

## 重置方法

```bash
cd dify
rm -f memory-store.json          # 或清空 PowerContext 中对应 player 的记录
python3 powercontext_bridge.py   # 重新启动，回到干净状态
```

重置后重复第一、二轮，结果应一致。连续操作顺序不可颠倒：必须先冷启动再复用，否则第二轮的「上次你说过」没有依据。
