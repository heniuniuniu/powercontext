# 验证样例：从导入到记忆复用

## 初始条件

- 只需 Python 3.9+ 即可跑通零依赖模式；
- 想验证**真实 PowerContext** 时，额外准备 Python 3.11+ 与官方 `powercontext` 包
  （SQLite 后端，无需数据库，无需 API Key），步骤见文末；
- 初始记忆为空：删除 `qoder/memory.json` 与 `qoder/.powercontext-scope` 即可；
- 初始资料：5 条示例切片，内容见 `server/search.py:SAMPLE`，覆盖
  `数据库 / 检索 / 工程 / 周报 / 记忆` 五个标签。

## 操作步骤（零依赖模式）

1. `cd qoder && python main.py` —— 打印 `SELFCHECK PASS` 并以退出码 0 结束，说明
   health / init / 混合检索 / 记忆复用 / 周报草稿全部可运行。
2. `python main.py --serve` 启动站点与 API 服务（**这一条才常驻**），浏览器打开
   `http://127.0.0.1:8899/`（网站与 API 同一端口），在检索框输入「向量索引刷新」并回车。
3. 观察命中结果：`notes/seekdb-week3.md` 排在首位，带出处与标签。
4. 观察「PowerContext 记忆」卡片：`recent` 出现本次主题，`topTag` 记为「数据库」。
5. 刷新页面（模拟新会话），输入「混合检索」再查一次；卡片仍显示上一轮的
   `recent`，且历史标签在排序中起作用。
6. 查看 `qoder/logs/run.log`：应有 `seekdb.hybrid_search` 与 `powercontext.read` 记录。

## 操作步骤（真实 PowerContext 模式）

```bash
cd qoder
python -m venv .venv
.venv/Scripts/pip install "powercontext[server]"
.venv/Scripts/powercontext config init --template --output .env.powercontext
.venv/Scripts/powercontext server run --env-file .env.powercontext --port 8765
```

另开终端：

```bash
cd qoder
POWERCONTEXT_URL=http://127.0.0.1:8765 .venv/Scripts/python main.py
```

预期输出：

```text
SELFCHECK PASS: health / init / hybrid search / memory reuse / weekly report
{"backend": "local", "powercontext": "powercontext", "memory_backend": "powercontext",
 "hits": 1, "recent": ["混合检索", "向量索引刷新"], "topTag": "数据库"}
```

再直接核对 PowerContext 里的记录：

```bash
curl -X POST http://127.0.0.1:8765/v1/memory/entries/list \
  -H 'Content-Type: application/json' \
  -d '{"scope_id":"<.powercontext-scope 中的 scope_id>","limit":10}'
```

应看到 `kind=检索记录` 的条目，文本形如
`主题=向量索引刷新；标签=数据库；用户=selfcheck；时间=...`。
完整输出与日志节选见 [`evidence/powercontext-live.md`](evidence/powercontext-live.md)。

## 预期结果

| 检查项 | 预期 |
| --- | --- |
| 网站可访问 | 无登录状态下可打开项目网站，含简介、痛点、功能、演示、仓库链接 |
| 混合检索 | 单次请求返回带出处的段落；接真实 seekdb 时在单条 SQL 内融合向量与全文，本地兜底时在同一函数内融合排序，均不拉两路结果到前端拼合 |
| seekdb 实际作用 | `logs/run.log` 有 `seekdb.hybrid_search` 及返回行数；SQL 见 `server/search.py` |
| PowerContext 实际作用 | `/health` 返回 `"powercontext": "powercontext"`；`/search` 返回 `"memory_backend": "powercontext"`；日志有 `powercontext.write` 与 artifact id；服务端 `entries/list` 能查到同一条记录 |
| 跨会话记忆 | 新进程/新页面再次检索时，`recent` 来自 PowerContext，且历史标签参与排序 |
| 周报草稿 | 按时间窗汇总检索记录，可在站点上编辑 |

## 重置方法

```bash
rm -f qoder/memory.json qoder/logs/run.log qoder/.powercontext-scope
# 如需清空 PowerContext 记忆，直接重建本地数据目录后重启服务：
# Windows: %LOCALAPPDATA%\powercontext；Linux/macOS: ~/.local/share/powercontext
# seekdb: DROP TABLE kb_chunk; 再 POST /init 重建
curl -X POST http://127.0.0.1:8899/init -H 'Content-Type: application/json' -d '{}'
```
