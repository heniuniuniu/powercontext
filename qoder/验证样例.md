# 验证样例：从导入到记忆复用

## 初始条件

- 一个可连接的 seekdb 实例（`SEEKDB_DSN`，占位值）与一个 PowerContext 服务
  （`POWERCONTEXT_URL`，占位值）；不配置时后端用本地 `memory.json` 兜底，
  前端站点用内置示例数据，流程仍可完整体验。
- 初始记忆为空：`qoder/memory.json` 不存在，或 `{"recent": [], "topTag": null}`。
- 初始资料：5 条示例切片，内容见 `site/app.js:SAMPLE`，覆盖
  `数据库 / 检索 / 工程 / 周报 / 记忆` 五个标签。

## 操作步骤

1. `python server/search.py`，另开终端 `python -m http.server 5173 --directory site`。
2. 打开 `http://127.0.0.1:5173`，在检索框输入「向量索引刷新」并回车。
3. 观察命中结果：`notes/seekdb-week3.md` 排在首位，带出处与标签。
4. 观察「PowerContext 记忆」卡片：`recent` 出现本次主题，`topTag` 记为「数据库」。
5. 刷新页面（模拟新会话），输入「混合检索」再查一次；卡片仍显示上一轮的
   `recent`，且历史标签在排序中起作用。
6. 查看 `qoder/logs/run.log`：应有 `seekdb.hybrid_search` 与 `powercontext.write` 两条记录。

## 预期结果

| 检查项 | 预期 |
| --- | --- |
| 网站可访问 | 无登录状态下可打开项目网站，含简介、痛点、功能、演示、仓库链接 |
| 混合检索 | 单次请求返回带出处的段落；检索在 seekdb 内完成，不拉两路结果到前端拼合 |
| seekdb 实际作用 | `logs/run.log` 有 `seekdb.hybrid_search` 及返回行数；SQL 见 `server/search.py` |
| PowerContext 实际作用 | `logs/run.log` 有 `powercontext.write`；刷新后 `recent` 仍存在并被用于排序 |
| 周报草稿 | 按时间窗汇总检索记录，可在站点上编辑 |

## 重置方法

```bash
rm -f qoder/memory.json qoder/logs/run.log
# seekdb: DROP TABLE kb_chunk; 再 POST /init 重建
curl -X POST http://127.0.0.1:8899/init -H 'Content-Type: application/json' -d '{}'
```
